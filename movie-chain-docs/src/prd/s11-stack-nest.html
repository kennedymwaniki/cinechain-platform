11Technology Stack — NestJS Edition

Every component below is chosen for a stated reason. Where the reason is “it is what the team knows”, that is said plainly — it is a legitimate reason and a better one than a fashionable choice nobody can operate.

11.1 Core choices

ConcernChoiceWhy this, and what we considered
LanguageTypeScript 5.x on Node 22 LTSOne language across API and web client. Strict mode is non-negotiable — a branded TenantId type catches a whole class of mistake at compile time.
FrameworkNestJS 11Chosen specifically for its interceptor and guard pipeline, which maps one-to-one onto the interception patterns multi-tenancy requires. The dependency-injection container also makes request-scoped tenant context natural rather than bolted on.
DatabasePostgreSQL 17Row-level security is the decisive feature. Also gives us the exclusion constraint for FR-22, tstzrange, partitioning and strong JSON support. MySQL has no comparable RLS.
Query layerDrizzle ORMGenerates SQL you can read, which matters enormously when auditing tenant scoping. Prisma is the popular alternative but its connection handling makes per-request SET LOCAL awkward — a decisive objection here.
Migrationsdrizzle-kit + raw SQL for policiesRLS policies and exclusion constraints are written as raw SQL and version-controlled alongside generated migrations.
Cache & locksRedis 7 (ioredis)Atomic SET NX EX and Lua scripting are exactly what §7.3 requires. Cluster mode from the start, since keys are already tenant-prefixed.
JobsBullMQRedis-backed, so no additional infrastructure. Per-tenant queue prefixes give fair processing across tenants.
AuthKeycloakSelf-hostable, supports custom claims and realm-per-tenant if ever needed. Auth0 is easier but prices per active user, which is punitive for a consumer ticketing flow.
Real-timeSocket.IO with Redis adapterSeat-map push (FR-33). Rooms are namespaced per tenant and screening.
ValidationZod + nestjs-zodOne schema produces both runtime validation and the TypeScript type.
LoggingPinoFast structured JSON; child loggers carry tenant context without call-site effort.
TracingOpenTelemetry → TempoTenant as a root-span attribute.
MetricsPrometheus + GrafanaTenant as a label, with the long tail bucketed to control cardinality.
TestingVitest + Testcontainers + k6Testcontainers gives a real PostgreSQL with real RLS — isolation cannot be meaningfully tested against a mock.
Web clientNext.js 15 + TanStack QueryServer rendering for film pages (they should be indexable); client state for the seat map.
DeploymentDocker → Kubernetes, HelmOne chart, one values file per tier. A silo is a values file.

On the tenancy/ directory

Keeping every tenancy mechanism in one directory is a deliberate organisational choice. It gives you a small, stable surface to protect: a CODEOWNERS rule requiring senior review on that path, a dedicated test suite, and an obvious place for a new engineer to read first. Tenancy logic scattered across forty files cannot be reviewed, only hoped about.
