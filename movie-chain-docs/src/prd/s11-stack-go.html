11Technology Stack — Go Edition

Go is a strong fit for this system specifically because the hot path is a high-concurrency, low-latency seat-lock service. Where that matters, it is said; where the choice is neutral, that is said too.

11.1 Core choices

LanguageGo 1.23+Goroutines make the seat-release stampede — thousands of connections waiting on a screening — cheap in a way threaded runtimes are not. Predictable latency matters more here than raw throughput.

What Go gives you here, and what it asks in return

Gives: context.Context is already threaded through every idiomatic function signature, including pgx's query methods. Tenant context is therefore not an ambient trick bolted onto the language — it uses the mechanism the language already has, and it is visible in every signature.

Asks: there is no framework to save you. Nothing prevents a developer writing a raw query with no tenant scope. You must build the guard rails yourself — a repository layer that derives the tenant from ctx, plus RLS underneath — and enforce them in review. Go trades magic for explicitness, and that trade is only good if you actually write the explicit parts.

Why internal/ matters more than usual here

Go's internal/ directory is enforced by the compiler: nothing outside this module can import it. Putting tenancy/ there means no future service, test helper or tool can reach around the tenant-scoping layer, even accidentally. Combine it with a CODEOWNERS rule on that path and you have a boundary the toolchain defends rather than a convention people remember.
