8API Design

8.1 Conventions

  • Base path /api/v1. The version is in the path because tenants integrate with it and cannot all be migrated at once.
  • Tenant is established differently for the two populations of §4.2, and this is the most important convention on the page:
    • Staff endpoints take it from the JWT tenant_id claim. It never appears in a path or query parameter.
    • Consumer endpoints have no tenant claim to read. The tenant is derived server-side from the resource — screening.tenant_id for a hold, the signed hold token for a booking. The caller supplies an object id; the server supplies the tenant.
  • Token type gates the endpoint. A token carrying tenant_id is a staff token and is rejected on consumer endpoints; a token without one is a consumer token and is rejected on staff endpoints. Both rejections are 403 and both are logged as security events.
  • Money is always an integer in minor units with an explicit currency. No floats, anywhere, ever.
  • Times are RFC 3339 with an offset. The theatre's timezone is returned alongside, because “the 20:30 showing” is a local-time concept.
  • IdempotencyStripe — Idempotent requestsBrandur — Idempotency keys — every state-changing endpoint accepts an Idempotency-Key header; payment endpoints require one.
  • Pagination is cursor-based. Offset pagination degrades badly on the large tables here.

8.4 Error model

StatusCodeWhen, and what the client should do
401no_tenant_contextA staff endpoint received a token with no tenant_id. Never defaulted — re-authenticate.
403wrong_token_typeA consumer token on a staff endpoint, or a staff token on a consumer endpoint. Logged as a security event; see §8.1.
401hold_token_invalidThe signed hold token is missing, malformed, expired or was minted for a different screening.
403tenant_mismatchThe requested resource belongs to another tenant. Logged as a security event with the attempted resource.
404not_foundAlso returned when a resource exists but belongs to another tenant — never 403, which would confirm its existence.
409seats_unavailableLost the race. Refresh the map and let the customer choose again.
410hold_expiredHold died before payment. Offer re-hold.
429rate_limitedTenant or user limit reached. Retry-After and the limit that was hit are both returned.
503payment_provider_unavailableHold is preserved where possible; the client should retry with the same idempotency key.
Why a cross-tenant request returns 404 rather than 403

Returning 403 for a resource that exists in another tenant confirms that it exists. Repeated across an ID space, that is an enumeration oracle: a competitor can map how many bookings a rival is taking by observing which identifiers return 403 and which return 404.

Return 404 for both “does not exist” and “exists but is not yours”. Log the difference internally as a security event — the client learns nothing, and you learn everything.
