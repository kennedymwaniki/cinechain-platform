17References

Two kinds of citation marker appear in this document: G ch. 8, p. 195 for the primary source, and Redis — SET command for freely available online material. Links checked 22 September 2026.

17.1 Primary source

  • Tod Golding — Building Multi-Tenant SaaS Architectures O'Reilly Media, 1st edition, May 2024. ISBN 978-1-098-14064-9.
    The source of the silo / pool / bridge vocabulary, the control-plane / application-plane split, and the “default to pooled” guidance adopted in ADR-001. Chapter references used in this document: ch. 2 (fundamentals, p. 23), ch. 3 (deployment models, p. 47), ch. 4 (onboarding and identity, p. 81), ch. 7 (building services, p. 157), ch. 8 (data partitioning, p. 189), ch. 9 (tenant isolation, p. 219), ch. 12 (operations, p. 307), ch. 14 (tiering, p. 363).
  • Companion volume — Multi-Tenant Architecture: A Masterclass The conceptual background to every tenancy decision in this PRD, written to be read first. Its Chapter 9 is the long-form version of ADR-001; its Chapter 20 carries a fuller reading list than this appendix.

17.3 PostgreSQL

Background for Section 6.

  • PostgreSQL — Row Security Policies, and CREATE POLICY The mechanism §6.4 depends on. Read the notes on table owners and FORCE ROW LEVEL SECURITY — that is where the classic mistake lives. postgresql.org/docs/current/ddl-rowsecurity.html postgresql.org/docs/current/sql-createpolicy.html
  • PostgreSQL — SET and SET LOCAL The difference between these two statements is the difference between working isolation and an intermittent cross-tenant leak under pooling (§12.2). postgresql.org/docs/current/sql-set.html
  • PostgreSQL — Range types and exclusion constraints Behind the no-overlapping-screenings guarantee, FR-22. postgresql.org/docs/current/rangetypes.html
  • Crunchy Data — Row Level Security for Tenants in Postgres A practical walkthrough of exactly the session-variable pattern used here. crunchydata.com/blog/row-level-security-for-tenants-in-postgres
  • Citus — Multi-tenant applications What Option A looks like past one machine: distribution by tenant, co-location, and when sharding beats siloing. Relevant to the revisit triggers in ADR-001. docs.citusdata.com/en/stable/use_cases/multi_tenant.html

17.4 The hold engine — concurrency and idempotency

Background for Section 7.

  • Redis — SET command, and the Distributed Locks pattern NX and EX are the atomic primitive §7.3 is built on. The locks page is honest about what a single-instance lock does and does not guarantee. redis.io/docs/latest/commands/set/ redis.io/docs/latest/develop/clients/patterns/distributed-locks/
  • Brandur Leach — Implementing Stripe-like Idempotency Keys in Postgres The clearest explanation of why idempotency keys are necessary and how to implement them against a relational database. Directly applicable to FR-51 and the failure table in §7.4. brandur.org/idempotency-keys
  • Stripe — Idempotency The retry contract the booking flow assumes of any payment provider. stripe.com/blog/idempotency docs.stripe.com/api/idempotent_requests
