The one sequencing rule

Tenancy is in P0, before any feature. This will feel wrong in week two, when there is one customer and nothing to show, and there will be pressure to “add tenant_id later”.

Retrofitting tenancy onto a live schema means re-partitioning production data, rewriting every query, re-issuing every credential and re-testing every endpoint — a quarter of work, under pressure, with customers watching. Doing it first costs about a week. This is the highest-leverage decision in the plan and the one most likely to be argued away.

15.2 Definition of done

A P0-critical story is not done until all of the following hold. These are checked at review, not asserted in a stand-up.

  • Every new table carries tenant_id, has RLS enabled and FORCEd, and has an isolation policy.
  • Every new endpoint appears in the generated isolation suite and passes it.
  • Every new index on a tenant-scoped table leads with tenant_id, or has a written justification.
  • Every new background job establishes tenant context from its payload.
  • Every new cache key, queue name and object-storage path is tenant-prefixed.
  • No tier name appears in business logic.
  • Logs and metrics emitted by the new code carry the tenant label.
  • The onboarding smoke test still passes.
